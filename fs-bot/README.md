# fs-bot：个人飞书 → 公司飞书 消息转发机器人

一个跑在你电脑（或任何常开设备）上的 Node.js 脚本：

- 通过**长连接（WebSocket）**接收**个人飞书**里机器人所在会话的消息事件——不需要公网服务器、不需要域名
- 把消息实时推送到**公司飞书**某个群的自定义机器人 Webhook

```
个人飞书                              本机脚本                     公司飞书
┌──────────────────────┐            ┌──────────────┐            ┌────────────────────┐
│ 自建应用「转发机器人」   │ WebSocket │ fs-bot       │   HTTPS    │ 群「个人消息汇总」     │
│  ├─ 机器人能力         │◀──────────│ relay.js     │───────────▶│  └─ 自定义机器人      │
│  └─ 长连接事件订阅      │  无需公网IP │ 过滤+格式化   │            │     (Webhook 地址)   │
└──────────────────────┘            └──────────────┘            └────────────────────┘
                                                     你在公司飞书的这个群里看到个人消息
```

## 能转发什么、不能转发什么（先看这个）

| 场景 | 能否转发 | 说明 |
|---|---|---|
| 机器人被拉进的个人飞书群 | ✅ 全部消息自动转发 | 前提：群属于你的「个人团队」（你建的群）。别人组织的群加不了你的机器人 |
| 别人发给你的私聊 | ❌ 无法自动 | 飞书隐私限制，任何机器人都看不到你与别人的单聊。**替代做法**：长按消息 → 转发 → 发给机器人，脚本会立刻转去公司飞书 |
| 你手动转给机器人的任何消息 | ✅ | 同上，一步操作 |
| 文字 / 富文本 | ✅ 转全文 | |
| 图片 / 文件 / 语音 / 视频 | ⚪ 显示占位符 | 公司账号本来也访问不了个人租户的文件 |

另注意：**脚本离线期间的新消息不会补发**（长连接断开事件就收不到），建议挂在常开设备上。

## 配置步骤

### 第一步：个人飞书侧——创建自建应用（约 10 分钟，只做一次）

1. 用**个人飞书**账号登录 <https://open.feishu.cn>。如提示需要企业/团队，按引导免费创建「个人团队」即可（个人版飞书就是这个形态，你本人就是管理员）
2. 开发者后台 → **创建企业自建应用**（名字随意，如"转发机器人"）
3. 左侧「添加应用能力」→ 启用 **机器人**
4. 左侧「权限管理」→ 开通以下权限：

   | 权限 | 用途 |
   |---|---|
   | 获取群组中所有消息（im:message.group_msg） | 收群消息，**必需** |
   | 读取用户发给机器人的单聊消息（im:message.p2p_msg） | 收手动转发的私聊，**必需** |
   | 获取群组信息（im:chat:readonly） | 显示群名，可选 |
   | 获取用户基本信息（contact:user.base:readonly） | 显示发送人姓名，可选 |

5. 左侧「事件与回调」→「事件配置」→ 订阅方式选择 **「使用长连接接收事件」** → 「添加事件」→ 搜索并添加 **接收消息 (im.message.receive_v1)**
6. 「版本管理与发布」→ 创建版本 → 申请发布（你是个人团队管理员，直接通过）
7. 「凭证与基础信息」页复制 **App ID** 和 **App Secret**
8. 在个人飞书里把机器人拉进要转发的群：群设置 → 群机器人 → 添加机器人 → 选刚创建的应用

### 第二步：公司飞书侧——群自定义机器人（约 2 分钟）

1. 在公司飞书建一个群当"收件箱"（可以只有你自己一个成员）
2. 群设置 → 「群机器人」→ 添加机器人 → **自定义机器人**
3. 复制 **Webhook 地址**；若勾选了「签名校验」，把密钥也记下来
4. 若公司禁止成员添加自定义机器人：此路不通，只能找公司管理员在公司租户上自建应用（成本高，先找 IT 确认）

### 第三步：配置并运行

```bash
npm install
copy config.example.json config.json    # 然后编辑 config.json 填入三个必填项
npm run test:webhook                    # 先验证公司侧：群里应出现测试消息
npm start                               # 正式启动，开始监听个人飞书
```

在个人飞书被拉进机器人的群里发条消息，公司飞书群里应马上出现。

### config.json 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| appId / appSecret | ✅ | 个人飞书自建应用的凭证 |
| webhookUrl | ✅ | 公司飞书群自定义机器人地址 |
| webhookSecret | | 自定义机器人的签名密钥，没开签名校验就留空 |
| forwardP2P | | 是否转发"手动转给机器人"的私聊，默认 true |
| includeGroups | | 只转发这些群（填群名或 chat_id），留空 = 全部 |
| excludeGroups | | 不转发这些群 |
| prefix | | 每条消息的前缀，方便一眼区分来源 |

### 常驻运行

- **最简单**：双击 `start.bat`。把它的快捷方式放进 `shell:startup`（Win+R 输入 `shell:startup`）即可开机自启
- **更稳**：pm2 —— `npm i -g pm2`，然后 `pm2 start relay.js --name fs-bot`、`pm2 save`
- 也可部署到 NAS / 树莓派 / 便宜 VPS 等任何常开设备

## 常见问题

- **启动报 401 / app_secret 不匹配**：确认 config.json 里填的是**个人飞书**应用的凭证，且复制时没带空格
- **群消息收不到**：逐项检查——事件订阅方式选了「长连接」、事件 `im.message.receive_v1` 已添加、权限 `获取群组中所有消息` 已开通、机器人已拉进该群、应用版本已发布
- **手动转发的私聊收不到**：检查权限 `读取用户发给机器人的单聊消息` 是否开通；转发目标是机器人（搜索机器人名字发起会话）
- **公司群里收不到**：先跑 `npm run test:webhook`；开了签名校验就必须填 `webhookSecret`
- **公司限制加自定义机器人**：需要公司管理员配合在公司租户建自建应用，改造成本高（找 IT）
- **自定义机器人有频率限制**（约 100 条/分钟），个人使用一般碰不到
